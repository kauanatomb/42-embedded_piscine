# Embedded Piscine – 42 Paris

This repository documents my work during the **Embedded Systems Piscine** at 42 Paris.

After building a strong foundation in systems programming (C, memory management, Unix processes) and later working on full-stack and backend applications, I wanted to go deeper, closer to the hardware layer.

This piscine was an opportunity to understand how software interacts directly with microcontrollers, timing constraints, and physical systems.

---

## 🔎 What I Explored

- Low-level programming on microcontrollers
- Hardware interaction through registers and peripherals
- Timing and scheduling using hardware timers
- Interrupt-driven programming
- Serial communication (UART)
- Analog signals and sensor data
- Communication protocols like I2C
- Implemented interrupt-based UART communication
- Built timer-driven scheduling logic

---

## 📚 Curriculum Overview

### Week 1
- Day 00: First programs (bare-metal basics)
- Day 01: Timers (precise timing and delays)
- Day 02: Interruptions (event-driven programming)
- Day 03: UART (serial communication)
- Rush 00: Multiplayer (team project combining concepts)

### Week 2
- Day 04: Advanced timers
- Day 05: Analog (ADC, signal reading)
- Day 06: I2C (device communication)

---

## 🧠 Key Takeaways

- Writing software without abstractions forces a deeper understanding of how systems actually work
- Timing, concurrency, and resource constraints become physical realities, not just concepts
- Interrupts and hardware events require a different mental model than traditional backend systems
- Debugging is more about reasoning than tooling
